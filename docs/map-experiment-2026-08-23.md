# 지도 축 고도화 실험 — 2026-08-23 (제단/도박 노드)

> 지도 축은 결정 격차 **1.1웨이브**로 미달이다(기준 1.5). 진단은 오래 서 있었다 — "자원이 생선
> 하나뿐이라 모든 경로 선택이 '더 벌까/덜 쓸까'로 수렴한다." 이 문서는 그 자리에 **전투가 아닌
> 행위**(도박)를 놓아 경로가 결정이 되게 하려 한 실험의 기록이다. 사전 등록 기준은 §0, 결과는 §2,
> 왜 실패했고 무엇이 실제로 통할지는 §3에 있다. 재현은 이 문서를 담은 커밋의 **부모 커밋**에서
> `npm run map -- 1500 0 --events`.

## 0. 사전 등록

- **가설**: 지도에 "제단(도박)" 노드를 놓는다. 그 길로 들어가면 생선을 걸고 슬롯을 돌린다 —
  `eventRelicChance`(0.55)로 유물이 나오거나, 아니면 가장 센 고양이가 지쳐 한 단계 내려간다(강해지거나
  약해지는 게 랜덤). **값이 상태에 달렸다**(생선 여유·유물 수·로스터 크기)면 상태를 읽는 경로 선택이
  결과를 가르고, 지도에 깊이가 생긴다.
- **A/B**: `BALANCE.mapEvents` 플래그 + `npm run map -- --events`. 정책 둘을 더한다 — "제단 몰빵"(보이면
  무조건 간다)과 "제단 읽고 고름"(생선 여유+유물 부족+로스터 두꺼울 때만).
- **채택 기준**: (1) 격차 ≥ 1.5, **두 시드 블록 모두** · (2) "제단 읽고 고름"이 "제단 몰빵"과 "무작위"를
  **의미 있게 이김**(깊이는 폭과 다르다 — placement-space가 명시한 구분) · (3) 중앙값 ±1.
- **기각 조건**: 격차가 늘어도 그것이 "제단 정책이 더 나쁘다"에서 나온 폭이면 기각. 코드를 걷어낸다.

## 1. 구현 (부모 커밋에 보존)

- `map.ts`: NodeKind `event` 추가, `assignKinds`가 플래그 켜졌을 때 걸음당 하나 배정, checkStage·nodeInfo 반영.
- `run.ts`: `chooseNode`의 event 분기 → `resolveEvent`(생선 차감 · rng로 유물 or 레벨 하락 · 유물은 몰빵
  직업 우선). 게임 난수를 쓰므로 시드로 재현된다.
- `icons.ts`·`render.ts`: 제단은 마름모 아이콘 · 금빛.
- `bot-policy.mjs`: `EVENT_MAP_POLICIES`(제단 몰빵·제단 읽고 고름). `map-space.mjs`: `--events` 플래그.
- `validator-test.mjs`: 제단 계약(꺼지면 없음 · 켜지면 등장·checkStage 유지 · 유물이면 생선 감소, 아니면 레벨 하락).

## 2. 결과 — 기각

| 정책 | A 시드 1~1500 | B 홀드아웃 1501~3000 |
|---|---|---|
| **읽고 고름**(기존 최선, 제단 안 씀) | **13.2** | **13.7** |
| 전투만 | 12.8 | — |
| 무작위 | 12.7 | — |
| **제단 읽고 고름** | 11.7 | 12.2 |
| **제단 몰빵** | 11.7 | 12.1 |
| 격차(최선−최악) | 1.5 | 1.6 |

격차는 1.1(기준선) → 1.5~1.6으로 올라 **관문에 닿았다. 그러나 이건 깊이가 아니라 폭이다.**

- **"제단 읽고 고름"(11.7)이 "제단 몰빵"(11.7)을 못 이긴다** — 상태를 읽어도 소용없다. 채택 기준 (2) 실패.
- **두 제단 정책 다 그냥 싸우는 것(전투만 12.8·읽고 고름 13.2)보다 나쁘다.** 제단은 **함정**이다 — 가면 손해다.
- 격차 1.5는 `읽고 고름(13.2) − 제단정책(11.7)`, 즉 "새로 생긴 못 깨는 길"에서 나온다. placement-space가
  "폭(배치를 망칠 수 있는가) ≠ 깊이(손으로 놓으면 자동보다 나은가)"라고 못 박은 그 폭이다.

두 블록에서 같은 패턴이라 잡음이 아니다. **기각.**

## 3. 왜 실패했나 — 그리고 무엇이 실제로 통할까

**제단은 엘리트의 열위 복제였다.** 엘리트는 유물을 **보장**하고 생선 1.6배까지 준다. 제단은 55%로 유물을
주면서(엘리트보다 나쁨) 45%로 레벨을 깎고 생선까지 뗀다. 유물을 원하는 정책은 제단이 아니라 엘리트로
가는 게 맞고("읽고 고름"이 이미 그렇게 한다), 그래서 제단은 아무 상태에서도 이득인 자리가 없다.

**순수 도박은 봇 하네스에서 깊이로 안 잡힌다 — 구조적 이유가 있다.** 지도 리서치(slaythespire 위키·
casino-roguelike 분석)가 정리한 원리: 도박의 **기대값은 살짝 플러스여도, 진짜 비용은 분산**이다. 분산은
**뒤처진 플레이어가 역전을 노려 쓰는 도구**(앞선 플레이어는 리드를 지키려 스킵)다. 그런데 봇은 "내가
지금 앞섰나 뒤졌나"를 못 읽고 위험 중립적이라, +EV가 크지 않은 분산은 그냥 평균을 낮추는 것으로 잡힌다.
즉 **이 하네스는 사람의 분산 관리(틸트·역전 도박)를 신용하지 못한다** — 도박이 사람에게 재미있을 수는
있어도, "봇이 상태를 읽어 체계적으로 이득"이라는 이 축의 정의로는 깊이가 아니다.

**지도에 진짜 깊이를 만드는 것은 "돈이 더 생김"이 아니라 봉쇄·트레이드·정보다**(리서치, 슬더슬 GDC·
Golden Idol·Wheel of Change). 다음 실험 후보를 깊이 순으로 남긴다 — **앞의 셋은 이 하네스로 측정
가능한 결정형(비랜덤), 뒤는 사람에게 값하나 봇으로는 안 잡히는 랜덤형이다:**

1. **비변환 열쇠 / 봉쇄** (측정 가능·최우선) — 생선으로 못 사는 자원(별사탕 2~3개 상한)으로 특정
   엘리트·보물 노드만 연다. **파워 0, 순수 봉쇄** — "이 경로를 타면 저 문은 영영 못 연다." 리서치가
   지목한 유일한 "파워 없이 순수 경로 깊이". 봇도 상태(열쇠 수·목표 노드)를 읽어 라우팅 → 측정 가능.
2. **대가 있는 트레이드 (Golden Idol형)** — 유물/유닛을 얻되 **대가를 고른다**(보드 슬롯 1칸 봉인 /
   생선 수급 −20% / 저주 유닛). 랜덤이 아니라 선택이라, "무엇을 내려놓을지"가 상태에 달려 깊이가 난다.
3. **정보/정찰 노드** — 다음 보스 편성·상점 재고 미리보기. 파워 0, 순수 정보 우위. 안전 경로의 보상.
   봇도 편성을 읽어 배치를 최적화 → 측정 가능.
4. **모닥불형 회복 vs 강화(택1)** — 보스 2/5 **직전**이면 "지금 버티기 vs 스케일링" 딜레마. 같은 노드가
   시점에 따라 정반대 결정 → 상태 의존. 측정 가능성 중간(봇의 회복 가치 판단이 거칠다).
5. **물고기 슬롯/룰렛 (랜덤·사람용)** — 사용자가 원한 도박. 하방은 생선 %로 **캡**(한 방 즉사 방지),
   확률을 조금씩 빚는 agency(Luck be a Landlord식)를 주면 사람에게 값한다. **단 봇 하네스로는 깊이가
   안 잡히므로**(§3 위), 이건 지도 관문을 여는 실험이 아니라 **사람 실험**(재미·재진입)으로 검증할 것.

## 4. 지도 ↔ 난이도 연결 (사용자 질문)

지도는 **결정 품질을 통한 난이도 손잡이**가 될 수 있다 — 스탯이 아니라. 어떤 노드가 똑똑한 라우팅을
보상하면(예: 좋은 경로로 유물을 더), 숙련자는 더 깊이 가고 무의식은 못 따라와 **결정 격차가 벌어진다**
(clear-space가 재는 그 격차). 그런데 지금 지도는 격차 1.1로 결정이 아니라, **난이도 게이트가 지도가
아니라 구매·유물·개입 축에 사는 이유**가 이것이다(docs/difficulty-qa-2026-08-23.md). 위 1~3번이 지도에
깊이를 만들면 그만큼 **새 난이도 손잡이**가 생긴다 — 제단(도박)은 그러지 못했다(함정이라 오히려 무의식·
숙련 모두를 똑같이 낮춘다).

## 5. 판정

- **제단(도박) 노드: 기각.** 코드 제거, 이 문서에 기록. 재현은 부모 커밋에서 `--events`.
- 지도 축은 여전히 미달(1.1/1.5). 다음은 **비변환 열쇠/봉쇄(§3-1)**가 최우선 — 파워를 안 더하고 경로를
  진짜 결정으로 만드는 유일한 길이라고 리서치가 지목했고, 봇 하네스로 측정 가능하다.
- 사용자가 원한 **랜덤 도박(슬롯)**은 사람에게 값할 수 있으나 이 축의 정의(봇이 상태를 읽어 체계적
  이득)로는 깊이가 아니다 — 넣는다면 지도 관문이 아니라 사람 실험으로 검증해야 한다.
