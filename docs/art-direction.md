# 냥 아레나 상황별 연출 명세 — 트랙 A

## 1. 공통 문법

- 판 위 고채도는 위험 `#FF3F6E`, 집합 `#2BE3B4`, 취약 `#FFE24A`만 쓴다.
- 정체성·보상·장식은 `paper`·`paperDim`·저채도 진영/직업색으로 물러난다.
- 신호는 색만 쓰지 않는다: 위험=사선, 집합=동심원, 취약=채운 고리.
- 전투 판정 시간과 렌더 시간은 섞지 않는다. 연출 때문에 `stepBattle`을 멈추거나 `RunState`를 바꾸지 않는다.
- HUD·버튼·안내는 카메라 연출에서 제외한다. 움직이는 것은 전장뿐이다.

## 2. 모션 정책

| 항목 | 기본 | `prefers-reduced-motion: reduce` |
|---|---|---|
| 예고 카운트다운 | fuse에 맞춰 외곽 원호/선 강조 | 정보이므로 그대로 유지 |
| 보스 등장 | 560~680ms, 전장 1.035→1.0 줌과 짧은 테두리 강조 | 줌·흔들림 없음, 정적 테두리 240ms |
| 저격수 등장 | 420ms, 전장 1.018→1.0 | 줌 없음, 정적 테두리 180ms |
| 보스 처치 | 기존 620ms 링·파편·화면 흔들림 | 흔들림·파티클 제거, 링만 유지 |
| 상점 구매 | 210ms 카드→도착 셀 이동 | 도착 지점 정적 표식만 160ms |
| 상주 장판/취약 | 저폭 맥동 | 중간 밝기로 고정 |
| 전환 막 | 1500ms 페이드 | 420ms 정적 표시, 페이드 없음 |
| 데미지 팝 | 위로 이동하며 감쇠 | 이동 없이 감쇠 |

숨김 탭에서는 기존 rAF 정지 계약을 그대로 사용한다. 복귀 시 렌더 시간 기준도 초기화해 떠나 있던 시간이
파티클·커튼·카메라 연출에 한꺼번에 더해지지 않게 한다.

## 3. 이벤트 명세

### 3-1. 위험 예고 — “나가라”

- 대상: circle/line/cone/half avoid.
- 팔레트: `T.danger`만 사용.
- 형태: 사선 해칭 + 외곽선. 원형은 중심 채움 대신 외곽 카운트다운 원호를 우선한다.
- 시간: `tg.fuse / tg.fuseMax`를 그대로 사용하며 새 타이머를 만들지 않는다.
- 레이어: 보드 위, 고양이 아래. 카운트다운은 외곽에 있어 몸과 숫자를 덜 가린다.
- 성능: 그라디언트/블러 없음. 기존 path에 stroke 1회만 추가한다.

### 3-2. 집합 예고 — “모여라”

- 팔레트: `T.gather`.
- 형태: 동심원 + 외곽 카운트다운 원호. 위험과 같은 타이머 문법을 쓰되 내부 무늬는 다르게 유지한다.
- 시간/성능: 위험 예고와 동일.

### 3-3. 취약 창 — “때려라”

- 팔레트: `T.vuln`.
- 형태: 기존 `drawVulnerableRing`의 시계 방향 소거 고리와 몸 뒤 글로우.
- 시간: 보스 킷의 `vulnerableMs`, 최종 국면은 `FINAL_VULNERABLE_MS`.
- 변경: 새 채움은 추가하지 않는다. 예고 중 데미지 팝 감쇠 규칙에서 치명타는 일반 숫자보다 높게 남긴다.

### 3-4. 타격·데미지 팝

- 평시: 현재 520ms, 최대 네 단계 계단 배치를 유지한다.
- 예고 활성 중: 일반 피해 숫자 알파/크기를 약 40%로 낮춘다. 회복·치명·회피는 약 65%로 남긴다.
- reduced-motion: 수직 이동을 없애고 자리에서 감쇠한다.
- 이유: 예고가 살아 있는 1.2초에는 “얼마나 때렸나”보다 “어디로 움직이나”가 먼저다.

### 3-5. 보스 등장

- 트리거: battle 국면에서 살아 있는 `radius > 0` 유닛의 uid가 새로 보일 때. `RunState` 필드 추가 금지.
- 일반 보스: 560ms, 스테이지 우두머리: 680ms, 저격수: 420ms.
- 형태: 전장 중심 기준 작은 줌아웃(최대 3.5%), 전장 외곽 종이색 이중선, 배너는 기존 체력바를 사용.
- 금지: 전투 dt 정지, 버튼 가리기, 화면 전체 흔들림, 새 고채도 색.
- reduced-motion: transform을 끄고 외곽선만 짧게 보여 준다.

### 3-6. 정예/저격수

- 지도: 기존 발톱 노드 이상 투자하지 않는다.
- 전투: 보스 등장 문법의 짧고 약한 변형만 사용한다. 배너 높이는 기존 72%, 문턱 눈금은 없음.
- 팔레트: `T.enemy`·`T.paperDim`; 위험 신호색을 위계 장식으로 쓰지 않는다.

### 3-7. 상점·보상

- 구매: 기존 카드→보드 210ms, 도착 링, 레벨업 불티, 생선 420ms 롤업을 유지한다.
- reduced-motion: 이동 경로를 없애고 도착 지점 표식으로 대체한다.
- 리롤: 새 파티클을 만들지 않는다. 카드 교체 자체와 생선 롤업이 피드백이다.
- 팔레트: 보상은 `paper`·`gold`·저채도 직업색. 판 위 신호색을 사용하지 않는다.

### 3-8. 승리·패배

- 보스 승리: 기존 bossdeath 링/파편, 전장 흔들림, “악몽을 밀어냈어요” 막을 유지한다.
- 일반 승리: 별도 모달 없음. 짧은 보상 notice와 지도 복귀가 리듬이다.
- 패배: 현재 부검 판과 재진입 3버튼을 유지한다. 배경 파티클을 더하지 않는다.
- reduced-motion: 보스 처치 흔들림과 커튼 페이드를 제거하되 결과 텍스트와 선택지는 즉시 읽히게 한다.

## 4. 구현 접점

| 변경 | 파일·함수 |
|---|---|
| 모션 선호 감지와 공통 분기 | `src/game/render.ts` 모듈 상단 |
| 예고 카운트다운/채움 축소 | `drawOneTelegraph`, `hatch`, `concentric` |
| 예고 중 숫자 감쇠 | `drawPops`와 `render` 호출부 |
| 보스 등장 스테이징 | `render` 전장 transform, `drawBossBanner` 주변 렌더 전용 상태 |
| 기존 효과 reduced-motion | `drawCreepZones`, vulnerable 함수, `drawFx`, `drawBuyTweens`, `drawCurtain`, `bossDeathShake`, `drawFinalPhaseOverlay` |

`battle.ts`, `bosses.ts`, `run.ts`, `balance.ts`의 상태·수치·수명은 읽기만 하고 수정하지 않는다.

## 5. 검증 계약

1. `npm run typecheck`, `npm test`, `npm run probe`, `npm run dodge:test`, `npm run invariants`, Vite build.
2. `npm run verify`는 기존과 같은 `map` 단독 실패여야 한다.
3. 6축 원시 구간 SHA-256과 정규화 `metrics` 게임 수치 SHA-256이 부모 커밋과 같아야 한다.
4. 금지 로직 파일과 의존성 파일 diff가 비어 있어야 한다.
5. 일반 모션과 reduced-motion에서 보스 등장·예고·상점·부검을 실제 브라우저로 확인한다.
6. 숨김 탭에서 rAF가 멈추고 복귀 시 `last = 0`으로 재개되는 기존 코드 경로를 유지한다.
