### Codex와 함께 게임을 만든 과정 — 5,000자 이내

```text
챌린지 초반에는 고양이 구매·배치·자동전투, 기본 보스 예고, 지도와 유물 루프가 동작하는 기본 프로토타입이 있었습니다. 제출 버전에서는 Codex를 저장소 분석, 기능 구현, UI 수정, 테스트와 출고 검증에 사용했습니다.

제가 먼저 정한 목표는 “다음 보스의 규칙을 플레이어가 고른다”였습니다. 위험과 보상의 허용 범위, 사용할 이미지와 연출, 런타임에서 OpenAI API를 호출하지 않는다는 원칙도 제가 결정했습니다. Codex는 이 방향을 실제 게임 코드로 옮겼습니다. 세 장의 악몽 계약 중 하나를 고르면 보스 패턴과 준비 경로, 승리 보상이 함께 바뀝니다. 직업 시너지는 입문 2마리, 도전 3마리, 악몽 3+3 조합으로 다시 구성했고, 같은 계약을 `?raid=` URL로 재현하는 기능도 추가했습니다.

가장 먼저 해결하려던 문제는 자동전투를 보고만 있어야 한다는 점이었습니다. Codex와 함께 붉은 산개, 청록 집결, 금빛 결정타를 만들고 회피 자원을 어디에 쓸지 직접 판단하게 바꿨습니다. 위험 선택도 단순한 수치 보너스가 아니라 일반전·정예·정찰 경로와 다음 보스의 판정, 추가 생선과 유물 보상까지 이어지도록 연결했습니다.

계약 데이터는 생성 결과를 그대로 실행하지 않습니다. Codex가 `RaidContract` 스키마와 허용된 보스 패턴 목록, 금지 값·중복 ID·수치 범위를 검사하는 검증기를 작성했습니다. 범위를 벗어난 값은 제한하고 검증에 실패하면 미리 정의한 안전 계약을 사용합니다. LLM은 후보 데이터를 만드는 빌드 단계에서만 쓰며, 배포된 게임은 검증을 통과한 JSON만 읽습니다.

UI 작업에서도 Codex를 반복적으로 사용했습니다. 화면 캡처를 기준으로 간격과 정렬을 다시 잡고, Maplestory 폰트와 직업별 색, 픽셀 아이콘, 공격·피격·스킬 효과를 적용했습니다. 전투가 다음 단계로 넘어가지 않던 흐름, 비활성처럼 보이던 회피 버튼, 작은 직업 표기처럼 플레이하면서 발견한 문제도 재현 테스트를 만든 뒤 수정했습니다. 포인터와 키보드 입력, 화면 회전, 모션 축소, 음소거, 숨김 탭 복귀, 1단계 보스 이후 2단계 진입은 실제 브라우저에서 다시 확인했습니다.

최종 판단은 제가 했습니다. Codex가 제안하거나 생성한 결과를 그대로 채택하지 않고, 게임 방향과 수치 범위, 자산의 채택·폐기, 문구와 화면의 우선순위를 직접 검토했습니다. 마지막에는 자동 검증으로 계약 선택, 구매, 배치, 전투 개입, 지도, 유물의 여섯 축을 확인했습니다. 계약을 읽는 정책은 보상만 보는 정책보다 도달 웨이브 중앙값이 14 대 6, 첫 두 보스 통과율이 96.5% 대 66.9%였습니다. 구현과 테스트 로그는 커밋과 저장소 문서에 남겨 다시 실행할 수 있게 했습니다.
```
