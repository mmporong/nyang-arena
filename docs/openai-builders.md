### 데모 영상 링크 — 선택 가산점

```text
https://mmporong.github.io/nyang-arena/submission-gameplay.mp4
```

`yuv420p`·CFR 30fps 영상이다. 게임 BGM을 AAC 48kHz 스테레오로 합성했다. QA 상태
주입 없이 하나의 런에서 계약 선택 → 위험별 지도 → 첫 고양이 2마리 영입 → 자연
공격·피격과 승리 → 다음 지도·상점·추가 전투 2회를 연속으로 보여 준다. 로컬 원본은
`public/submission-gameplay.mp4`이며 위 공개 URL에서 바로 재생된다.

```text
[Codex 중심 개발 방식]

[생성 결과를 믿지 않는 구조]
Codex는 좁은 RaidContract 스키마와 BossPattern 화이트리스트를 연결하고 후보·적대 입력 검증 파이프라인을 만들었습니다. 생성 결과를 바로 실행하지 않고 금지 토큰, 중복 ID, 허용 범위, 패턴 조합을 검사합니다. 범위 밖 수치는 클램프하고 실패하면 안전 계약으로 폴백합니다. LLM은 빌드타임 후보 생성에만 사용하며, 배포 게임은 외부 네트워크 요청 없이 검증을 통과한 JSON만 읽습니다.

[Codex가 해결한 제품 문제]
첫째, 자동 전투를 바라보기만 하던 보스전에 “다음 규칙을 내가 고른다”는 사전 결정과 제한된 전투 개입을 연결했습니다. 둘째, 위험 선택이 숫자 장식에 머물지 않도록 준비 경로·보스 판정·추가 보상까지 하나의 인과로 묶었습니다. 셋째, 읽기 어려운 카드와 전투 피드백을 Maplestory 폰트, 직업별 색, 정렬된 정보 밴드, 픽셀 아이콘·공격·피격·스킬 VFX로 재구성했습니다. 넷째, 포인터·키보드, 화면 회전, 모션 축소, 음소거·숨김 탭, 스테이지 전환을 실제 브라우저에서 검사했습니다. 다섯째, 보드·배경·틴트 캐시에 LRU 상한을 두고 5K·8K에서도 FX 버퍼를 100만 픽셀 이하로 제한했습니다.

[검증 증거와 평가 기준 정합성]

Presentation: 시작 즉시 계약 세 장으로 핵심 선택을 보여주고, 붉은 산개·청록 집결·금빛 취약 신호와 선택·구매 피드백으로 규칙과 결과를 화면에서 전달합니다. 성능·밸런스 수치는 생성된 metrics와 6축 원시 해시로 재현할 수 있습니다.
```
