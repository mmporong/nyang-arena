> 기준일: 2026-08-24 · 작업용 문서

## 1. 결론

냥 아레나는 기존 오토배틀러를 그대로 내는 대신, 제출 버전의 첫 화면과 보스 규칙을
**악몽 계약** 중심으로 바꾼다. 플레이어는 검증된 계약 세 장 중 하나를 골라 다음
보스의 패턴·위험·추가 보상을 정하고, 위험에 맞는 준비 경로를 고른다. 이 루프의
분석·제품 명세·데이터 DSL·검증기·게임 상태·UI·공유 URL·헤드리스 검증은 이번
Codex 작업에서 새로 개발한다.

기존 Claude/사람 작업을 Codex 작업으로 재표기하지 않는다. 제출 문구는 다음 경계를
그대로 쓴다.

> 기존 프로토타입을 바탕으로, 챌린지 제출 버전의 핵심 차별화 루프인 악몽 계약
> 시스템은 Codex가 분석·설계·구현·검증했습니다.

## 2. 공식 평가 기준

공식 사이트가 이름을 공개한 평가는 다섯 축이다. **배점·가중치·동점 기준은 공개되지
않았다.** 아래 설명은 공식 명칭과 약관의 심사 문구를 냥 아레나에 적용한 운영 해석이며,
숫자 배점으로 오해하면 안 된다.

| 공식 축 | 심사에서 확인할 내용 | 냥 아레나의 제출 증거 | 현재 미흡·리스크 |
|---|---|---|---|
| Playability | 브라우저에서 즉시 작동하는가, 핵심 루프가 재미·명료한가, 안정적인가 | 첫 화면 계약 3장, 실제 보스 패턴 교체, 위험별 준비 경로, 포인터·1/2/3, 10기기 probe, 6축·불변식, 공개 번들 SHA 일치 | 실제 포인터·Digit3·모바일·스피커 수동 QA가 필요 |
| Originality | 단순 장르 복제가 아니라 기억할 규칙과 주제가 있는가 | “내가 다음 보스 규칙을 고른다”는 악몽 계약, 위험-보상-준비 경로, 서버 없는 계약 공유 | 계약 설명이 첫 화면에서 5초 안에 읽히는지 실제 캡처 확인 필요 |
| Codex Collaboration | Codex가 어디에 쓰였고 어떤 기능·문제를 해결했는가, 사람 판단과 경계가 보이는가 | 후보·적대 입력·검증기·채택 JSON·게임 적용·holdout·6축 해시, 확정 커밋과 CI artifact, `docs/codex-contribution.md` | 발표에서 기존 기반·Codex 신규 작업·사람 결정을 같은 비중으로 명확히 구분해야 함 |
| Release Potential | 공개·배포 가능한 완성도와 확장성, 향후 서비스 가능성이 있는가 | 설치/로그인 없음, GitHub Pages, 런타임 의존성·외부 요청 0, 계약 팩 데이터 확장, `?raid=` 비동기 공유 | 한국어 단일 언어, 서버 리더보드·Hive 연동 없음. Track 1 필수는 아니므로 과장하지 않음 |
| Presentation | 썸네일·설명·영상이 게임의 차별점을 빠르게 전달하는가 | 첫 30초 계약 선택, 고정 3분 동선, 코드→거절→채택→플레이의 한 줄 서사 | 기존 영상·썸네일은 새 계약 루프 이전 버전. 최신 실플레이로 교체해야 함 |

약관은 여기에 행사 목적 적합성, 규정 준수, 게임플레이, 기술 구현·안정성,
독창성·테마, 데모 적합성도 심사 고려사항으로 적는다. 따라서 “Codex를 썼다”는
설명만으로는 부족하고, 실제 게임 규칙과 공개 빌드에서 그 기여가 보여야 한다.

## 3. 공개된 가점과 제출 필드

공식 문서에서 명시적으로 확인되는 선택 가점은 두 가지뿐이다. 숨은 점수나 추가
가점을 추측하지 않는다.

1. **3분 이내 실제 플레이 데모 영상**
2. **Codex 활용 설명** — 어디에 사용했는지, 어떤 기능을 구현했는지, 어떤 문제를
   해결했는지, 사람이 무엇을 결정했는지를 설명

필수 제출 필드는 제목, 200자 이내 게임 소개, 공개 브라우저 플레이 링크, 썸네일이다.
썸네일은 16:9 JPG/PNG, 10MB 이하가 권장된다. 플레이 링크는 심사 기간 내내 별도
승인·복잡한 설치 없이 열려야 하며, 조작·실행 안내를 제공한다. 로그인이 필요하면
심사용 테스트 계정도 제공해야 하지만 이 게임은 로그인 자체를 요구하지 않는다.

| 제출물 | 상태 | 출고 기준 |
|---|---|---|
| 제목 | 준비 | `냥 아레나 (Nyang Arena)` |
| 200자 소개 | 준비 | 아래 확정안, 자동 글자 수 검사 |
| 공개 플레이 | 배포 완료 | <https://mmporong.github.io/nyang-arena/> · 최신 main 배포와 로컬/공개 번들 SHA 일치 |
| 썸네일 | 교체 필요 | `docs/thumbnail.png`, 최신 계약 첫 화면 또는 계약 보스 장면 1280×720 |
| 3분 영상 | 교체 필요 | 기존 영상 재사용 금지, 새 계약 선택과 실제 보스 판정을 포함 |
| Codex 설명 | 준비 | 아래 확정안 + `docs/codex-contribution.md` |

런타임 OpenAI API 호출은 공개된 Track 1 필수 조건이 아니다. 이 프로젝트는 Codex로
개발한 게임과 재현 가능한 생성·검증 파이프라인을 제출하며, 심사 중 API 키·잔액·
레이트리밋으로 게임이 죽는 위험을 피하려고 런타임 호출을 넣지 않는다.

## 4. 일정·자격·권리

- Track 1 접수: **2026-08-04~08-26**. 공식 페이지와 약관에 마감 시각·시간대가
  공개되지 않아 08/26 당일 마감으로 가정하지 않고 검증 즉시 제출한다.
- 예선 심사: 08/27, 본선 진출 안내: 08/28~30, 현장 Track 2: 08/31.
- 최종 수상 심사를 받으려면 본선에서 팀 대표 또는 사전 승인된 팀원이 현장 발표와
  시연을 해야 한다. 진출 시 참석 담당자와 오프라인 데모를 즉시 확정한다.
- 본선은 40팀, 팀은 최대 3명이며 Mollet은 1인 팀으로 충족한다.
- 기존 프로젝트도 허용되지만 챌린지 기간 전후의 개선 내용을 명확히 밝혀야 한다.
- 코드·이미지·음원·폰트·AI 산출물·OSS를 포함한 모든 제출 요소의 권리와 라이선스를
  확보해야 한다. 침해·유해/불법 콘텐츠, 악성 코드, 무단 개인정보 수집은 배제 사유다.
  고양이·배경·Canvas 아이콘은 자체 제작이고 BGM 생성 기록은 `docs/audio-prompts.md`에
  남아 있다. 최종 폼에서 권리 확인 문구를 다시 읽고 사실대로 확인한다.
- 제목·설명·썸네일·영상·게임플레이/발표 영상·수상 결과는 행사 채널에 공개될 수 있다.
  소스·비공개 저장소·비공개 기술자료는 별도 동의 없이 공개 대상이 아니므로 제출 문안에
  비밀·민감한 로컬 경로를 넣지 않는다.
- IP는 참가자에게 남고, 주최 측은 행사 홍보를 위한 비독점 사용권을 받는다. 수상작을
  제3자와 상업화 계약 또는 구체 협상하려는 경우 행사 뒤 4개월간 주최 측에 먼저 서면
  협상 기회를 주는 조항이 있다. 상업화 자체가 강제되는 것은 아니다.

## 5. 기존 게임과 이번 Codex 기여의 경계

### 기존 기반

- 고양이 구매·배치·자동 전투·보스 예고·재도전
- 기존 시너지 DSL과 검증기
- Canvas 2D VFX·Web Audio·스프라이트 파이프라인
- 지도·유물·측정 하네스

### 이번 제출 버전에서 Codex가 새로 만든 핵심

- `RaidContract` 제한 스키마와 기존 `BossPattern` 재조합 규칙
- 후보 6개, 적대 입력 8개, 거절·클램프·안전 폴백 파이프라인
- 첫 화면 계약 3장과 포인터/키보드 선택, 지도 입력 차단
- 선택 계약의 보스 패턴·후반 패턴·위험 배율·승리 보상 적용
- 낮음→일반 전투, 중간→정예, 높음→정찰 준비 경로와 지도 이중 고리
- 보스 승리 뒤 중복 없는 유물 3장 중 하나를 고르고 일반 상점으로 잇는 드래프트
- `?raid=NA1-<seed36>-<contract-id>` 공유·자동 로드
- 계약 holdout, 고위험 정찰 통제 실험, 레이아웃·흐름·적대 테스트
- 6축 원시 로그 SHA-256과 재현 가능한 metrics 연결

세부 추적표는 `docs/codex-contribution.md`가 소유한다.

## 6. 제출 문안

### 게임 소개 — 200자 이내

```text
첫 화면에서 악몽 계약을 골라 다음 보스의 패턴·위험·보상을 직접 정하는 픽셀 고양이 오토배틀러. 계약 위험에 맞춰 일반전·정예·정찰 경로를 고르고, 붉은 산개·청록 집결·금빛 취약 신호에 제한된 개입으로 답하세요. 같은 계약은 URL로 공유됩니다.
```

### Codex 활용 설명

```text
기존 프로토타입을 바탕으로 챌린지 제출 버전의 핵심 루프인 ‘악몽 계약’을 Codex가 분석·설계·구현했습니다. Codex는 제한된 BossPattern DSL, 후보/적대 입력, 검증기, 첫 화면 3장 선택, 실제 보스 패턴·위험·보상 적용, 위험별 준비 경로, ?raid= 공유, 유물 택1 드래프트를 만들었습니다. 생성 후보는 그대로 실행하지 않고 금지 토큰·중복·범위를 검사해 6개만 출고합니다. 사람은 방향 전환, 위험·보상 범위, 저품질 캐릭터 폐기, 런타임 API 미사용을 결정했습니다. 최종 채택은 6축, 계약별 전수 holdout, 유물 ablation, 불변식으로 검증한 뒤 확정합니다.
```
