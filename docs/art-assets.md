# 냥 아레나 아트 에셋 파이프라인과 필요 목록 — 트랙 B

## 1. 이번 트랙의 경계

이번 범위는 기존 파이프라인을 재현 가능한 순서로 정리하고, 새 픽셀아트를 만들 사람에게
필요 에셋을 넘기는 데까지다. 새 포즈·보스 원화·배경 원화는 만들지 않으며, 런타임 코드와
전투 규칙도 바꾸지 않는다.

## 2. 현재 재고 실측

2026-08-23 작업 트리 기준이다.

| 구분 | 실측 | 계약 |
|---|---:|---|
| 캐릭터 스프라이트 | 186장 | 31 ID × 6포즈 |
| 포즈 | 각 31장 | `idle/sleep/wink/move/back/run` |
| 스프라이트 규격 | 전부 197×197 RGBA | 균일 셀·투명 배경 |
| 아이콘 | 논리 17종 | Canvas 2D 패스 17종 · 이미지 파일 0장 |
| 원본 시트 | 1374×4306 RGBA | 저장소 밖 `CatCharacterSheet.png` |
| 생성 도구 | Python 3 + Pillow 12.1.1 실측 | 런타임 의존성 아님 |

`src/game/sprites.ts`는 시작할 때 게임에 쓰는 ID의 6포즈를 전부 로드한다. 한 장이 실패해도
게임은 뜨고 렌더러의 Canvas 폴백 도형으로 내려가지만, 출고 에셋은 186장이 모두 있어야 한다.

## 3. 정준 파이프라인

### 3-1. 입력

- 정준 원본: 저장소 밖 `PKM/06_Ideas/assets/CatCharacterSheet.png`.
- 다른 기기에서는 `NYANG_SHEET`에 절대경로를 준다.
- 원본은 6열 × 20행이다. 열은 `idle/sleep/wink/move/back/run`, 셀은 197×197,
  시작점 `(124,144)`, 피치 208px이다.
- 원본 대용량 시트는 커밋하지 않고, 생성된 개별 PNG만 `public/sprites/`에 커밋한다.

PowerShell 실행 순서:

```powershell
cd $HOME\nyang-arena
$env:NYANG_SHEET = "$HOME\PKM\06_Ideas\assets\CatCharacterSheet.png"
npm.cmd run slice
npm.cmd run recolor
Remove-Item Env:NYANG_SHEET
```

### 3-2. 슬라이스

`scripts/slice-sprites.py`가 원본 20행을 `public/sprites/01_*`~`20_*` 120장으로 자른다.

- 배경 제거는 셀 테두리에서 시작하는 flood fill만 쓴다. 전역 색상 치환은 흰색·크림색
  몸통까지 지우므로 금지한다.
- 타이트 크롭을 하지 않는다. 197×197 셀을 유지해야 포즈 전환 때 발 위치가 튀지 않는다.
- 파일명은 `<2자리 ID>_<pose>.png`다.

### 3-3. 리컬러

`scripts/recolor-sprites.py`가 20개 원본 중 지정된 바탕을 색조 변환해 ID 21~31의 66장을
미리 굽는다. 런타임 `hue-rotate`는 쓰지 않는다.

| 새 ID | 바탕 ID | 용도 |
|---:|---:|---|
| 21~24 | 01, 04, 08, 02 | 아군 청록·보라·연두·분홍 변형 |
| 25~28 | 20, 15, 13, 18 | 악몽 청록·보라·연두·분홍 변형 |
| 29~31 | 05, 06, 07 | 소환사 남색·노랑·진홍 변형 |

리컬러는 명암 순서와 알파를 보존하고 색상·채도를 덮어쓴다. 원본과 파생본은 같은
197×197 앵커를 공유한다.

### 3-4. 출고 검수

다음 조건을 모두 만족해야 생성 결과를 스테이징할 수 있다.

1. `public/sprites/`에 PNG가 정확히 186장이고 ID 01~31이 각각 6장이다.
2. 여섯 포즈별 개수가 각각 31장이다.
3. 전 파일이 197×197 RGBA이며 투명 배경을 가진다.
4. 각 포즈의 몸 중심과 발바닥 기준선은 같은 ID의 `idle` 대비 ±2px 안이다.
5. 불투명 픽셀이 비어 있지 않고, 흰색·크림색 몸통에 flood fill 구멍이 없다.
6. 리컬러 11종은 바탕과 실루엣·알파가 같고 색만 다르다.
7. 브라우저에서 10기기 프로브, 실제 보드 100%·150% 크기, 밝고 어두운 배경을 확인한다.
8. 결과 파일만 경로별로 스테이징하고 `git diff --cached --stat`으로 범위를 확인한다.

슬라이스·리컬러 스크립트 자체는 빈 셀을 경고하고 계속하거나 바탕 포즈가 없으면 조용히
건너뛴다. 대신 `npm run asset:test`가 출고 전에 31 ID × 6포즈의 정확한 파일명,
197×197 RGBA PNG 헤더를 fail-closed로 검사한다. ID 31의 리컬러 로그 이름이 현재 품종명
`허깨비`가 아니라 옛 이름 `메아리`로 남은 문제는 다음 파이프라인 변경에서 고친다.

## 4. 필요 에셋 목록

### P0 — 전투 가독성에 직접 필요한 포즈

| 에셋 | 새 원화 수 | 예상 런타임 수 | 규격 | 필요한 이유 |
|---|---:|---:|---|---|
| `attack` 키 포즈 | 원본 ID 01~20 각 1장 = 20 | 리컬러 포함 31 | 197×197 RGBA | 근접·원거리 공격을 `idle` 흔들림이 아닌 실루엣으로 구분 |
| `hit` 키 포즈 | 원본 ID 01~20 각 1장 = 20 | 리컬러 포함 31 | 197×197 RGBA | 피격 플래시만으로는 누가 맞았는지 난전에서 놓침 |

한 동작당 한 장만 요구한다. 시작·회수는 기존 `idle/move`와 코드 트윈으로 연결해 원화 수를
늘리지 않는다. 파생 ID 21~31은 현재 리컬러 매핑을 그대로 적용한다.

### P1 — 능력과 상태를 구분하는 포즈

| 에셋 | 새 원화 수 | 예상 런타임 수 | 규격 | 필요한 이유 |
|---|---:|---:|---|---|
| `stun` 키 포즈 | 원본 ID 01~20 각 1장 = 20 | 리컬러 포함 31 | 197×197 RGBA | 정지·기절을 단순 idle과 구분 |
| `cast` 키 포즈 | 기존 시트 ID 02·05·09·10·11·12·14·18 = 8, 소환사 29~31 전용 3 = 11 | 리컬러 파생 24·28 포함 13 | 197×197 RGBA | 마법·보스 예고·소환을 일반 공격과 구분 |

소환사 29~31은 원본 바탕 05~07의 직업 실루엣과 역할이 다르므로 `cast`만은 리컬러 복제로
만들지 않고 전용 원화를 받는다.

### P2 — 사건성과 무대 확장

| 에셋 | 수량 | 규격 | 용도 |
|---|---:|---|---|
| 보스 컷인 초상 | 4장(ID 09~12) | 394×197 RGBA, 투명 배경 | 보스 등장 프레임의 선택적 고해상도 강조 |
| 스테이지 2·3 배경 콘셉트 | 2장 | 1440×900 기준 PNG, 저채도 | 아직 전용 무대가 없는 밤의 방향성 확정 |

P2는 바로 런타임에 넣는 산출물이 아니다. 먼저 콘셉트로 승인한 뒤 Canvas 배경으로 옮길지,
래스터를 로컬 번들할지 성능 측정으로 결정한다.

## 5. 아티스트·이미지 생성 모델 전달 규격

- 캔버스 197×197, 투명 RGBA, nearest-neighbor 전제, 안티앨리어싱·반투명 외곽선 금지.
- 몸 중심·발바닥 기준선은 같은 ID의 기존 `idle`을 그대로 맞춘다. 캔버스 크기를 바꾸거나
  타이트 크롭하지 않는다.
- 판 위 고채도 신호 3색(`#FF3F6E`, `#2BE3B4`, `#FFE24A`)을 몸의 넓은 면에 쓰지 않는다.
- 보스 컷인도 실루엣·무늬·눈 색을 기존 197×197 스프라이트와 일치시킨다.
- 이미지 생성 모델은 콘셉트·컷인 후보에는 쓸 수 있지만, 포즈 시트 최종본은 앵커와 픽셀
  일관성을 사람이 정렬·검수해야 한다.

## 6. 이번 트랙에서 만들지 않는 것

- 예고·취약·타격 파티클 시트: 트랙 A의 Canvas 2D 코드로 이미 해결했다.
- 추가 직업·유물 아이콘: 현재 논리 아이콘 17종이 Canvas 매니페스트·런타임 계약과 일치한다.
- 새 리컬러 품종: 31 ID가 모두 6포즈를 가진다.
- 새 BGM·효과음: 이 문서의 아트 에셋 범위 밖이다.
