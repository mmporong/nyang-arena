# 냥 아레나 (Nyang Arena)

### ▶ [지금 해보기 — mmporong.github.io/nyang-arena](https://mmporong.github.io/nyang-arena/)

설치도 로그인도 없다. 링크를 열면 바로 시작한다.
`?debug=1`을 붙이면 `window.nyang`으로 내부 상태를, `window.nyangTelemetry()`로
실제 플레이 시간을 꺼내 볼 수 있다(둘 다 네트워크를 쓰지 않는다).

브라우저에서 바로 돌아가는 **픽셀 고양이 오토배틀러**.

**사람이 잠들면 고양이가 그 밤에 든 것을 밀어낸다.** 악몽에는 형체가 없어서
고양이의 모습을 빌려 쓰는데, **한 번도 우리 고양이로는 오지 않는다** — 어디서
본 것 같은데 이름을 모르는 열두 마리다. 위로 갈수록 밤이 깊어지고, 여섯 걸음
안에 되풀이되는 것이 둘 있다.

5×5 보드에 고양이를 배치하고, 자동 전투를 관전하고, 악몽을 얼마나 깊이 밀어내는지 겨룬다.

제출 버전은 **악몽 계약 세 장에서 시작한다.** 하나를 고르면 다음 보스의 패턴,
위험 배율, 추가 생선이 실제로 바뀐다. 낮음은 일반 전투, 중간은 정예, 높음은
정찰로 대비하며 계약 직후 세 길이 모두 열린다. 추천 길은 금색 이중 고리로 표시되고,
다른 길을 고르면 계약 보스의 체력·광역 피해가 3% 강해진다. 선택 주소의
`?raid=NA1-...` 코드를 공유하면 다른 기기에서도 같은 시드와 첫 계약을 연다.

**매 판의 규칙이 다르다.** 시너지 세 개는 LLM이 생성한 풀에서 뽑히고,
어떤 조합을 세우느냐에 따라 켜지는 시너지가 달라진다.

## 플레이

한 걸음의 순서는 **길 → 적 → 준비**다. 상대를 보면서 사고 놓는 것이 한 화면에서 일어난다.

1. **악몽 계약을 고른다.** 규칙·대응·위험·추가 생선을 비교하고 1/2/3 또는 카드로 선택한다
2. **지도에서 길을 고른다.** 얕은 잠·가위눌림·숨 돌리기 중 무엇을 밟을지, 그리고
   계약 위험에 맞는 보상을 고른다. 세 갈래는 다음 확인 전투에서 합쳐져 경로 운이
   준비 효과를 가리지 않는다. **같은 줄의 칸은 저마다 다른 것을 낸다**
3. 고르는 순간 **상대가 정해진다.** 같은 화면에서 **영입·강화·교체** 중에서
   고르고, 우리 편 5×5 보드에 **드래그해서 배치**한다. 마음에 안 들면 다시 뽑는다.
   무엇을 살지와 어디에 놓을지는 같은 판단의 앞뒤라 화면을 가르지 않았다
4. **싸우러 가기** — 고양이들이 직접 걸어나가 싸운다. 근접은 붙으러 달려가고, 원거리는 뒤에서 쏜다
5. **보스를 이기면 유물 드래프트가 열린다.** 서로 다른 유물 세 장 중 하나만 고르거나
   건너뛴 뒤, 같은 보상 국면의 일반 상점으로 이어진다. 조건·정확한 이득·대가를 읽고
   지금 보드에 맞는 유물을 고른다
6. 한 걸음마다 적이 강해지고 **성격도 바뀐다**(뒤섞인·달려드는·멀리서 노리는 것들, 그리고 대장묘). 정찰도 시간이 흐르는 선택이라 깊이는 오르지만 전투는 피한다. 전멸하면 도달한 악몽 깊이가 기록된다
7. **죽은 화면은 부검이다** — 무엇에 막혔나, 예고를 몇 번 피했나, 어떤 팀이었나, 그리고
   **도감**(데리고 있던 고양이·모은 유물·만난 보스가 기기에 쌓인다). 그 아래 세 갈래가 있다:
   **같은 시드**(판은 그대로, 선택만 바꿔 본다 — 운이 아니라 내 탓인지), **오늘의 시드**(날짜에서
   뽑은 시드라 오늘은 누구나 같은 판이다 — 서버 없이 성립하는 비동기 경쟁, 기록은 기기에만 남는다),
   **도전 +1**(단계마다 적이 8% 세진다, 기록은 단계별로 따로). 영구 파워 해금은 없다 — 더
   강해지는 대신 **다른 규칙으로 다시** 한다

**무엇과 싸울지 알고 산다**는 것이 이 순서의 전부다. 멀리서 노리는 것들이 오는데
원거리를 사거나, 달려드는 것들이 오는데 앞줄을 비우는 일이 없어지고, 같은 카드가
판마다 다른 값을 갖는다.

게임을 켜면 고양이 셋과 생선 여덟 마리를 들고 **첫 보스 계약 세 장에서 시작한다.**

고양이는 **전사·도적·궁수·마법사·소환사** 다섯 중 하나이고 각자 고유 능력을 하나 갖는다.
열다섯 중 열셋은 마나가 차면 터지는 **액티브**, 둘은 늘 켜져 있는 **패시브**다.

회전베기·대지 강타·감싸기(전사), 그림자 일격·급소치기(도적), 꿰뚫기·화살비(궁수),
불씨·서리 발톱·핥아주기(마법사), 떼부르기·버팀목·미끼 세우기(소환사)가 액티브고,
연격(줄줄이 — 같은 적을 때릴수록 빨라진다)과 도탄(삼색이 — 근처로 튕긴다)이 패시브다.
소환사는 자기 화력이 가장 낮은 대신 판에 몸을 더 내보낸다 — 우리 쪽에만 있는 직업이다. 무엇을 하는 고양이인지는 **사기 전에 카드에 적혀 있다.**

**도적은 전투가 시작되면 상대 뒷줄로 뛰어든다** (0.3초에 걸쳐 달려 건너간다). 원거리를 한쪽에 몰아 두면 그대로
물리므로, 근접을 뒤에도 세우거나 흩어 놓아야 한다. 상대 도적도 똑같이 움직인다.

건너편에 서는 열둘(문틈이·덮침이·뜬눈이·스침이·울음이·부름이·먼지털·입김이·
진땀이·멍울이·곰팡이·열꽃이)은 **우리 고양이와 한 마리도 겹치지 않는다.** 직업과
스탯은 우리 쪽 열둘과 일대일로 맞물려 있어서(소환사 셋만 짝이 없다 — 악몽은
형체가 없어 무엇을 불러낼 수 없다) 싸움의 저울은 그대로지만, 난전에서 겹쳐도 내 고양이가 어느
것인지 헷갈릴 일이 없다. 편은 머리 위 체력 바 색으로 갈린다.

화면 아래에는 **이번 판의 목표 3개**가 있다. 각 칩이 조건, 진행도, 얻는 효과를 함께
보여준다. 셋은 서로 방해하지 않으므로 **다 달성하면 세 효과가 모두 적용된다.**

| 목표 | 달성 방법 |
|---|---|
| 같은 색 | 같은 털색 3마리 |
| 같은 품종 | 같은 품종 2마리 |
| 앞줄 근접 | 적에게 가까운 열에 근접 2마리 |
| 뒷줄 원거리 | 가장 먼 열에 원거리 2마리 |

뒤의 둘은 배치를 요구한다. 무엇을 사느냐와 어디에 놓느냐가 한 시스템으로 묶인다.
배치에는 규칙이 하나 더 있다 — **같은 직업이 상하좌우로 붙으면 한 마리당 공격 +8%**(최대
2마리). 자동 배치는 붙이지 않으므로 손으로 대형을 잡을 값이 여기서 난다. 다만 저격과
장판 앞에서는 뭉친 대형이 벌을 받는다 — 보너스가 정답이 아니라 대형의 일부다
([`docs/experiments-2026-08-23.md`](docs/experiments-2026-08-23.md) §2).
목표는 4웨이브마다 새로 뽑히므로 한 번 맞추고 끝이 아니다.

## AI를 어디에 썼나

이 게임에서 AI는 **게임 규칙을 만드는 자리**에 있다. 대사나 장식이 아니다.
기존 시너지 DSL과 제출 버전의 보스 계약 DSL 둘 다 후보→검증→채택 경계를 쓴다.

```
개발 시간                              배포 후 런타임
─────────────────────────────         ──────────────────────
LLM이 시너지 규칙 후보 생성            data.json에서 3개 추출
        ↓                              (네트워크 호출 0건)
검증기: 화이트리스트 통과 검사
        ↓  범위 밖 수치는 클램프
        ↓  허용되지 않은 트리거·효과는 폐기
src/data/synergies.json 로 커밋

Codex가 악몽 계약 후보 생성
        ↓
검증기: 기존 BossPattern 화이트리스트·길이·중복·범위 검사
        ↓  위험/보상은 안전 범위로 클램프
        ↓  laser_beam·delete_board·raw half 등은 계약 전체 폐기
src/data/raid-contracts.json 로 커밋
```

핵심은 생성이 아니라 **압축**이다. LLM 출력을 그대로 실행하면 게임이 깨지거나
밸런스가 무너진다. 그래서 출력을 좁은 DSL로 강제하고, 통과하지 못한 것은 버리고,
통과한 값도 게임이 감당하는 범위로 누른다. 출고 6개 중 하나라도 잘못되면 부분
혼입 없이 안전 계약 3장으로 전체 폴백하고 이유를 debug 상태에 남겨 게임은 계속 돈다.

**AI가 후보를 내고, 무엇을 채택할지는 측정이 정한다.** 네 단계 전부 명령 하나로
재현된다 — 같은 시드면 같은 결과가 나온다.

```bash
npm run gen:synergies   # 생성 (키가 없으면 커밋된 후보를 쓴다)
npm run gen:contracts   # 악몽 계약 후보 검증·출고
npm test                # 검증 — 적대 입력 11개 → 폐기 8, 통과 3(값은 눌림)
npm run contract:test   # 계약 적대 입력·첫 화면·공유·승패 보상
npm run contracts       # 홀드아웃 1800시드 계약 선택 깊이
npm run map             # 실제 준비 전이 300시드 + 지도 정책 공간 1500런
npm run relics          # 2000시드 유물 드래프트·직업별 한계효과
npm run sim             # 시뮬 — 런 300회, 시드 1~300
npm run verify          # 채택 — 검증 6축을 재고 기준 미달이면 exit 1
```

밸런스 파라미터를 "이게 재밌을 것 같다"로 정한 적이 없다. 스윕을 돌리고 판정을
읽고 그대로 따랐다. 시드별 승자 신탁은 경로마다 RNG 소비가 갈려 짝비교가 아니라는
귀무검정 결과 때문에 합격 근거에서 제외했다. 대신 맵 축은 실제 준비 전이와
1500런 독립 평균을 함께 막는다. 효과 ≥1.0, 읽는 정책 ≥무작위, 고정 최선 격차 ≤0.5를
동시에 요구해 일부러 나쁜 정책 하나로 폭만 키우는 우회도 막았다. 계약 축은 출고
6개를 1800개 홀드아웃 시드의 첫 두 보스에 각각 강제해 독립 평균과 95% 구간으로 비교한다. 유물 축은
같은 직업 집중 정책에서 유물만 켜고 끄는 대조군을 함께 재어 선택 자체의 한계효과를
분리한다. 최신 6축
원시 출력 해시와 계약 holdout은 [`docs/generated/metrics-current.md`](docs/generated/metrics-current.md)에
기록된다. 과거 제출 시점의 빨간 관문은 [`docs/submission.md` §4](docs/submission.md)에
역사 기록으로 남겨 현재 기준과 섞지 않는다.

검증기가 실제로 막는지는 테스트로 증명한다:

```
$ npm test
적대 입력 11개 → 폐기 8개, 통과 3개
  quad_color     허용되지 않은 trigger: same_color_4
  finisher       허용되지 않은 effect.key: instant_kill
  9bad_id        id 형식 위반
  dup_id         id 중복: dup_id
  stringy        effect.value가 유한한 수가 아님
  ...
통과했지만 값이 눌린 항목:
  overshoot      atk_mul=1.6   (원본 9.9 → 상한으로 클램프)
  tag_soup       name="태그scriptalert(1)"  (꺾쇠 제거)
```

## 밸런스를 어떻게 잡았나

눈대중으로 맞추지 않았다. 게임 로직을 브라우저 없이 그대로 돌리는 하네스로
도달 웨이브 분포를 측정하고 튜닝했다.

```
$ npm run sim
런 300회 (정책: 살 수 있으면 가장 비싼 것 구매, 재배치 없음)
  최소 1  p25 6  중앙값 13  p75 21  최대 41
  ↑ 이 값은 npm run sim이 지금 내는 것으로 갱신한다. 원본은 docs/generated/metrics-current.md
```

이 과정에서 실제로 잡은 결함:

- 레벨 성장이 선형이라 웨이브 2에서 전멸 → 지수 성장으로 교정
- 강화 비용이 선형이라 후반에 무한히 강해짐(12%가 상한 도달) → 비용도 지수로
- 보드가 꽉 찼을 때 영입 카드가 남아 무한 재시도 → 오퍼에서 제거
- 타임아웃을 체력 비율로 판정해 런이 안 끝남 → 타임아웃은 패배로
- 전사 스킬이 원거리의 3~6분의 1밖에 안 나감 → 전사는 맞을 때도 마나가 차게
- 5x5에서 영입한 고양이가 뒷줄부터 채워져 근접이 여섯 칸을 걸어감 → 직업별 자동 배치
- 평타 전력이 마법사 1 대 도적 4로 벌어짐 → 스탯 재조정
- 달려드는 것들이 사망의 1%밖에 안 됨(전부 근접이라 씹힘) → 이동 속도 1.45배

## 개발

**재현 검증은 Node 24.12.0을 사용한다.** 측정 스크립트가 `--experimental-strip-types`로
TypeScript를 그대로 임포트한다(브라우저와 헤드리스가 같은 코드를 쓰기 위한
장치다). `.nvmrc`와 Pages CI도 같은 정확 버전에 고정했으므로 `nvm use` 뒤의
6축 로그·구조화 증거·metrics가 같은 런타임을 기록한다.

```bash
nvm use            # 또는 Node 24.12.0을 직접 설치
npm ci
npm run dev        # 개발 서버
npm run build      # 타입체크 + 프로덕션 빌드
npm test           # 검증기 적대 테스트
npm run audio:runtime:test # Web Audio 스케줄·정리·음소거·숨김 전환
npm run asset:test # 외부 아이콘 0장·Canvas 17종·186장 스프라이트 계약
npm run map        # 위험별 준비 경로 + 통제 보스 A/B
npm run qa:manual  # Windows: 자동 사전점검 + 실제 화면·청취 2문항 QA
npm run sim        # 밸런스 시뮬레이션
npm run verify     # 위 전부 + 불변식 + 결정 축 전체 (관문)
```

제출 직전 수동 확인은 `npm run qa:manual` 한 번으로 묶었다. 관련 자동 테스트·빌드와
공개 HTML·JS·PNG·OGG 응답, 로컬/배포 번들 SHA-256 일치를 먼저 검사한 뒤 브라우저에
실제 Pages 계약 화면과 로컬 신호 QA 페이지를 연다. 사람은 포인터·Digit3·공유 URL·추천
경로·계약 보스·재시도 흐름과 Canvas 아이콘·900×320·신호음 3종만 두 문항으로 판정한다. 결과는 Git 비추적 증거
`.omx/evidence/manual-qa-latest.md`에 기록된다. QA 페이지는 개발 서버 전용이며
프로덕션 빌드에는 포함하지 않는다.

결정 축 측정(`relics`·`map`·`placement`)은 시드 블록을 워커에 나눠 돈다(`scripts/parallel.mjs`,
기본 min(6, 코어−1)개). 결과는 순서대로 돌린 것과 바이트까지 같다 — `WORKERS=1 npm run map`과
`npm run map`의 출력을 diff하면 확인된다. 집계는 워커가 아니라 원래 자리에서 한 벌만 한다.

런타임 의존성 0개. 번들 크기는 `docs/generated/metrics-current.md`가 매번
다시 재서 적는다 — **여기에 숫자를 적어 두면 낡는다.**

### 다른 기기에서 시작할 때

`npm ci` 다음에 바로 되는 것과, 별도 준비가 필요한 것이 갈린다.

| 명령 | 추가로 필요한 것 |
|---|---|
| `dev` `build` `test` `sim` `verify` 등 | **없다.** Node 24.12.0이면 끝 |
| `npm run docs` (PDF) | python3 + `pip install markdown` + Chrome/Chromium |
| `npm run slice` (스프라이트 재생성) | python3 + Pillow + 원본 시트. **보통 필요 없다** — `public/sprites/`의 결과물 186장이 커밋돼 있다. 원본을 옮겼다면 `NYANG_SHEET=/경로/CatCharacterSheet.png npm run slice` |
| `npm run gen:synergies` | `OPENAI_API_KEY`. 없으면 커밋된 후보 파일을 쓴다 |

`git clone` 주소가 SSH(`git@github.com:...`)라 새 기기에서는 SSH 키를 등록하거나
HTTPS로 바꿔야 한다.

## 기술

TypeScript · Vite · Canvas 2D · Web Audio. 엔진·프레임워크 없음.
음악은 준비곡 하나가 지도·상점·배치·일반 전투를 통째로 흐르고, **보스전에만**
0.8초 크로스페이드로 갈아탄다(일반 전투는 3~4초라 전용 곡을 두면 판이 토막 난다).
붉은 위험·청록 집결·금빛 취약 신호는 파일 요청 없이 Web Audio로 합성하고,
같은 예고가 여러 프레임 유지돼도 상승 순간에만 한 번 울린다. 숨은 탭에서는
게임 루프와 오디오를 함께 멈춘다. 음소거는 HUD 오른쪽 끝 또는 `M`.
아트는 자체 제작 픽셀 고양이 20종 × 6포즈 시트를 `npm run slice`로 잘라 쓴다 —
우리 8종, 악몽 8종, 보스 4종으로 스무 장을 다 쓴다. 그 위에 `npm run recolor`가
밝기만 남기고 색을 갈아 우리 7종(직업별 셋째 넷 + 소환사 셋)·악몽 4종을 더 만들어
지금은 우리 15종·악몽 12종이다.
