# 냥 아레나 (Nyang Arena)

브라우저에서 바로 돌아가는 **픽셀 고양이 오토배틀러**.
5×5 보드에 고양이를 배치하고, 자동 전투를 관전하고, 몇 웨이브까지 버티는지 겨룬다.

**매 판의 규칙이 다르다.** 시너지 세 개는 LLM이 생성한 풀에서 뽑히고,
어떤 조합을 세우느냐에 따라 켜지는 시너지가 달라진다.

## 플레이

한 걸음의 순서는 **길 → 적 → 구매 → 배치**다.

1. **지도에서 길을 고른다.** 전투·정예·정찰 중 무엇을 밟을지, 그리고 어느 갈래로
   갈지가 다음 선택지를 좁힌다
2. 고르는 순간 **상대가 정해진다.** 그 상대를 보면서 **영입·강화·교체·유물** 중에서
   고른다. 마음에 안 들면 다시 뽑는다
3. 우리 편 5×5 보드에 고양이를 **드래그해서 배치**한다 (마우스·터치 모두 가능)
4. **전투 시작** — 고양이들이 직접 걸어나가 싸운다. 근접은 붙으러 달려가고, 원거리는 뒤에서 쏜다
5. 웨이브마다 적이 강해지고 **성격도 바뀐다**(혼성·돌격·저격·대장묘). 전멸하면 도달 웨이브가 기록된다

**무엇과 싸울지 알고 산다**는 것이 이 순서의 전부다. 저격대가 오는데 원거리를
사거나 돌격대가 오는데 앞줄을 비우는 일이 없어지고, 같은 카드가 판마다 다른 값을
갖는다.

게임을 켜면 고양이 셋과 생선 여덟 마리를 들고 **지도에서 시작한다.**

고양이는 **전사·도적·궁수·마법사** 넷 중 하나이고 각자 고유 능력을 하나 갖는다.
여덟 중 여섯은 마나가 차면 터지는 **액티브**, 둘은 늘 켜져 있는 **패시브**다.

회전베기·대지 강타(전사), 그림자 일격(도적), 꿰뚫기(궁수), 불씨·서리 발톱(마법사)이
액티브고, 연격(줄줄이 — 같은 적을 때릴수록 빨라진다)과 도탄(삼색이 — 근처로 튕긴다)이
패시브다. 무엇을 하는 고양이인지는 **사기 전에 카드에 적혀 있다.**

**도적은 전투가 시작되면 상대 뒷줄로 뛰어든다.** 원거리를 한쪽에 몰아 두면 그대로
물리므로, 근접을 뒤에도 세우거나 흩어 놓아야 한다. 상대 도적도 똑같이 움직인다.

화면 아래에는 **이번 판의 목표 3개**가 있다. 각 칩이 조건, 진행도, 얻는 효과를 함께
보여준다. 셋은 서로 방해하지 않으므로 **다 달성하면 세 효과가 모두 적용된다.**

| 목표 | 달성 방법 |
|---|---|
| 같은 색 | 같은 털색 3마리 |
| 같은 품종 | 같은 품종 2마리 |
| 앞줄 근접 | 적에게 가까운 열에 근접 2마리 |
| 뒷줄 원거리 | 가장 먼 열에 원거리 2마리 |

뒤의 둘은 배치를 요구한다. 무엇을 사느냐와 어디에 놓느냐가 한 시스템으로 묶인다.
목표는 4웨이브마다 새로 뽑히므로 한 번 맞추고 끝이 아니다.

## AI를 어디에 썼나

이 게임에서 AI는 **게임 규칙을 만드는 자리**에 있다. 대사나 장식이 아니다.

```
개발 시간                              배포 후 런타임
─────────────────────────────         ──────────────────────
LLM이 시너지 규칙 후보 생성            data.json에서 3개 추출
        ↓                              (네트워크 호출 0건)
검증기: 화이트리스트 통과 검사
        ↓  범위 밖 수치는 클램프
        ↓  허용되지 않은 트리거·효과는 폐기
src/data/synergies.json 로 커밋
```

핵심은 생성이 아니라 **압축**이다. LLM 출력을 그대로 실행하면 게임이 깨지거나
밸런스가 무너진다. 그래서 출력을 좁은 DSL로 강제하고, 통과하지 못한 것은 버리고,
통과한 값도 게임이 감당하는 범위로 누른다. 전부 버려져도 프리셋으로 폴백해서
게임은 반드시 돈다.

검증기가 실제로 막는지는 테스트로 증명한다:

```
$ npm test
적대 입력 11개 → 폐기 8개, 통과 3개
  quad_color     허용되지 않은 trigger: same_color_4
  finisher       허용되지 않은 effect.key: instant_kill
  9bad_id        id 형식 위반
  dup_id         id 중복: dup_id
  stringy        effect.value가 유한한 수가 아님
  ...
통과했지만 값이 눌린 항목:
  overshoot      atk_mul=1.6   (원본 9.9 → 상한으로 클램프)
  tag_soup       name="태그scriptalert(1)"  (꺾쇠 제거)
```

## 밸런스를 어떻게 잡았나

눈대중으로 맞추지 않았다. 게임 로직을 브라우저 없이 그대로 돌리는 하네스로
도달 웨이브 분포를 측정하고 튜닝했다.

```
$ npm run sim
런 300회 (정책: 살 수 있으면 가장 비싼 것 구매, 재배치 없음)
  최소 2  p25 9  중앙값 12  p75 18  최대 37
  ↑ 이 값은 npm run sim이 지금 내는 것으로 갱신한다. 원본은 docs/generated/metrics-current.md
```

이 과정에서 실제로 잡은 결함:

- 레벨 성장이 선형이라 웨이브 2에서 전멸 → 지수 성장으로 교정
- 강화 비용이 선형이라 후반에 무한히 강해짐(12%가 상한 도달) → 비용도 지수로
- 보드가 꽉 찼을 때 영입 카드가 남아 무한 재시도 → 오퍼에서 제거
- 타임아웃을 체력 비율로 판정해 런이 안 끝남 → 타임아웃은 패배로
- 전사 스킬이 원거리의 3~6분의 1밖에 안 나감 → 전사는 맞을 때도 마나가 차게
- 5x5에서 영입한 고양이가 뒷줄부터 채워져 근접이 여섯 칸을 걸어감 → 직업별 자동 배치
- 평타 전력이 마법사 1 대 도적 4로 벌어짐 → 스탯 재조정
- 돌격대가 사망의 1%밖에 안 됨(전부 근접이라 씹힘) → 이동 속도 1.45배

## 개발

**Node 22.6 이상이 필요하다.** 측정 스크립트가 `--experimental-strip-types`로
TypeScript를 그대로 임포트한다(브라우저와 헤드리스가 같은 코드를 쓰기 위한
장치다). 그 아래 버전에서는 `npm run sim` 계열이 전부 실패한다. `.nvmrc`가
있으므로 `nvm use`면 맞는다.

```bash
nvm use            # 또는 Node 22.6+ 를 직접 설치
npm ci
npm run dev        # 개발 서버
npm run build      # 타입체크 + 프로덕션 빌드
npm test           # 검증기 적대 테스트
npm run sim        # 밸런스 시뮬레이션
npm run verify     # 위 전부 + 결정 축 전체 (관문)
```

런타임 의존성 0개. 번들 크기는 `docs/generated/metrics-current.md`가 매번
다시 재서 적는다 — **여기에 숫자를 적어 두면 낡는다.**

### 다른 기기에서 시작할 때

`npm ci` 다음에 바로 되는 것과, 별도 준비가 필요한 것이 갈린다.

| 명령 | 추가로 필요한 것 |
|---|---|
| `dev` `build` `test` `sim` `verify` 등 | **없다.** Node 22.6+ 면 끝 |
| `npm run docs` (PDF) | python3 + `pip install markdown` + Chrome/Chromium |
| `npm run slice` (스프라이트 재생성) | python3 + Pillow + 원본 시트. **보통 필요 없다** — `public/sprites/`의 결과물 120장이 커밋돼 있다. 원본을 옮겼다면 `NYANG_SHEET=/경로/CatCharacterSheet.png npm run slice` |
| `npm run gen:synergies` | `OPENAI_API_KEY`. 없으면 커밋된 후보 파일을 쓴다 |

`git clone` 주소가 SSH(`git@github.com:...`)라 새 기기에서는 SSH 키를 등록하거나
HTTPS로 바꿔야 한다.

## 기술

TypeScript · Vite · Canvas 2D. 엔진·프레임워크 없음.
아트는 자체 제작 픽셀 고양이 20종 × 6포즈 시트를 `npm run slice`로 잘라 쓴다
(T1 빌드는 8종 사용).
